# PartPostKrimeaLocal

Программа для локального хранения, обработки и быстрого поиска отправлений партионной почты.

Приложение представляет собой веб-интерфейс, работающий локально или на сервере. Пользователь может загружать файлы с данными об отправлениях, после чего информация обрабатывается и становится доступной для быстрого поиска.

## Возможности

* Загрузка файлов с данными об отправлениях.
* Обработка Excel-файлов.
* Автоматическое добавление данных в локальную базу.
* Поиск отправлений через веб-интерфейс.
* Поиск без учёта регистра символов.
* Поиск по номеру отправления.
* Поиск по внутреннему номеру.
* Быстрый просмотр информации об отправлении.
* Работа с локальной базой данных.
* Автоматическое отслеживание появления новых файлов.
* Одностраничный веб-интерфейс.
* Возможность запуска локально.
* Возможность развёртывания в контейнерной среде.

---

## Назначение программы

`PartPostKrimeaLocal` предназначена для упрощения работы с данными об отправлениях партионной почты.

Вместо ручного поиска информации в больших Excel-файлах пользователь может загрузить файлы в программу и выполнять поиск через удобный веб-интерфейс.

Программа может использоваться для:

* поиска отправлений;
* проверки информации по номеру отправления;
* поиска по внутреннему номеру;
* обработки новых Excel-файлов;
* организации локальной базы отправлений;
* быстрого доступа сотрудников к информации.

## Поиск

В программе реализован поиск по нескольким параметрам.

### Поиск по номеру отправления

Введите номер отправления в поле поиска.

Программа выполнит поиск соответствующей записи в базе данных.

### Поиск по внутреннему номеру

Также поддерживается поиск по внутреннему номеру отправления.

Это позволяет находить информацию даже в случаях, когда номер почтового отправления неизвестен.

### Поиск без учёта регистра

Поиск не зависит от регистра букв.

Например, следующие варианты будут обрабатываться одинаково:

```text
AB123456789RU
ab123456789ru
Ab123456789Ru
```

### Основные файлы

#### `app.py`

Основной файл веб-приложения.

Отвечает за:

* запуск сервера;
* обработку HTTP-запросов;
* загрузку файлов;
* поиск отправлений;
* взаимодействие с базой данных;
* возврат данных в веб-интерфейс.

#### `config.py`

Файл конфигурации приложения.

Содержит настройки, необходимые для работы программы.

#### `db.py`

Модуль для работы с базой данных.

Используется для:

* создания структуры базы данных;
* добавления записей;
* поиска информации;
* получения данных об отправлениях.

#### `excel_processor.py`

Модуль обработки Excel-файлов.

Отвечает за:

* чтение загруженных файлов;
* извлечение данных;
* подготовку информации;
* передачу данных в базу.

#### `watchdog_handler.py`

Модуль автоматического отслеживания файлов.

Может использоваться для обработки новых файлов, появляющихся в отслеживаемой директории.

#### `templates/`

Содержит HTML-шаблоны веб-интерфейса.

#### `static/`

Содержит статические файлы:

* CSS;
* JavaScript;
* изображения;
* дополнительные ресурсы интерфейса.

#### `uploads/`

Директория для хранения загружаемых файлов.


# Работа с файлами

## Загрузка через веб-интерфейс

Файлы можно загружать непосредственно через интерфейс программы.

После загрузки файл:

1. сохраняется в рабочей директории;
2. передаётся на обработку;
3. считывается модулем обработки Excel;
4. данные добавляются или обновляются в базе;
5. становятся доступными для поиска.

---

## Папка `uploads`

Папка `uploads` используется для хранения файлов, которые должны быть обработаны программой.

Файлы можно добавлять:

* **до запуска приложения**;
* **во время работы приложения**, если включено отслеживание директории;
* **через веб-интерфейс загрузки**.

Если используется автоматическое отслеживание файлов, программа должна иметь права на чтение и запись в директорию `uploads`.

# Работа с Docker

Если проект запускается в Docker, рекомендуется убедиться, что контейнер имеет доступ к необходимым директориям.

При изменении исходного кода необходимо пересобрать образ.

Пример:

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

Для просмотра логов:

```bash
docker compose logs -f
```

Для остановки контейнеров:

```bash
docker compose down
```

# Права доступа

Программа должна иметь права на:

* чтение файлов;
* запись файлов;
* создание директории `uploads`;
* изменение файлов базы данных;
* доступ к временным директориям.

В Linux можно проверить права:

```bash
ls -la
```

При необходимости изменить владельца рабочей директории:

```bash
sudo chown -R $USER:$USER .
```

Или изменить права доступа к необходимой директории:

```bash
chmod -R 755 uploads
```

> Не рекомендуется без необходимости устанавливать права `777`, особенно на сервере.

# Возможные проблемы

## Ошибка `Permission denied`

Причина обычно связана с отсутствием прав на запись в:

* `uploads`;
* директорию базы данных;
* подключённый Docker volume.

Необходимо проверить права доступа пользователя или контейнера.

---

## Ошибка `Unexpected token '<' ... is not valid JSON`

Обычно это означает, что JavaScript ожидает JSON-ответ от сервера, но вместо JSON сервер вернул HTML-страницу.

Например:

* страницу ошибки `404`;
* страницу ошибки `500`;
* HTML-шаблон.

Необходимо проверить:

1. правильность URL в JavaScript;
2. существование соответствующего маршрута в `app.py`;
3. HTTP-статус ответа;
4. фактический ответ сервера.

---

## Ошибка `Cannot read properties of undefined`

Ошибка JavaScript вида:

```text
Cannot read properties of undefined
```

означает, что код пытается получить доступ к свойству объекта, который не был найден или имеет значение `undefined`.

Следует проверить:

* структуру JSON-ответа;
* наличие поля перед обращением к нему;
* обработку пустых результатов поиска;
* соответствие JavaScript фактическому ответу сервера.

---

## Файл загрузился, но данные не появились

Проверьте:

1. поддерживается ли формат файла;
2. соответствует ли структура Excel ожидаемому формату;
3. появились ли ошибки в логах;
4. имеет ли приложение доступ к базе данных;
5. действительно ли файл был обработан;
6. не возникла ли ошибка при добавлении данных.

---

## Изменения в коде не отображаются в Docker

После изменения исходных файлов старый контейнер может продолжать использовать ранее собранный образ.

Выполните:

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

После этого проверьте:

```bash
docker compose logs -f
```

# Безопасность

Если приложение разворачивается на сервере, рекомендуется:

* не публиковать служебные файлы в открытом доступе;
* ограничить доступ к интерфейсу загрузки;
* настроить резервное копирование базы данных;
* проверять тип и размер загружаемых файлов;
* запускать контейнер с минимально необходимыми правами;
* использовать reverse proxy и HTTPS при внешнем доступе.
